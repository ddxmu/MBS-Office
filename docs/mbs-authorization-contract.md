# Mbs 自有授权接口契约（迁移目标 v1）

本契约定义自有实现；它不表示当前版本已经覆盖全部原生调用。本机已安装 0.1.42，通过修改原编辑器内部入口接管已核实流程，安全回退保留 0.1.41 和 0.1.40。

## 唯一授权来源

授权管理入口为 `https://ttys.ddxmu.com/admin/mbs-licenses`。客户端只信任本站服务端签名、绑定当前账号／安装设备／会话且未过期的有效激活。旧序列号、旧会员状态、旧试用状态和旧本地授权文件不能补足或覆盖此决定。

登录成功与编辑授权分开。签名有效仅证明响应可信；响应还必须包含有效的 activation 元数据。`expired`、`revoked`、`device_limit`、缺少激活、签名错误、设备不符、会话不符、到期均不能开启编辑。旧版兑换响应有 activation 但没有 activationState 时兼容其已验签的有效绑定。

## 网站接口

沿用现有接口，避免引入第二套账号或变更已有设备数据库：

| 接口 | 用途 |
| --- | --- |
| POST `/api/mbs/login` | 账号登录，取得会话 |
| GET `/api/mbs/me` | 校验会话与账号 |
| POST `/api/mbs/logout` | 退出并撤销会话 |
| POST `/api/mbs/activation/auto` | 获取当前设备可用授权；新账号仅首次自动发放一年标准授权 |
| POST `/api/mbs/activation/redeem` | 兑换管理员生成的授权码 |
| GET `/api/mbs/activation/status?deviceId=UUID` | 展示当前设备状态；展示结果本身不能替代签名授权 |

自动激活、兑换请求使用 Bearer 会话、安装设备 UUID 和随机 nonce。兑换额外提供 code。请求不得提交原厂 SN、旧账号 cookie 或旧激活记录。

签名响应沿用现有 P-256/SHA-256 envelope：payload、signature、keyId。已签名载荷核对 issuer、audience、authority、账号、设备、sessionHash、nonce、issuedAt、expiresAt、jti，以及 activation 的授权编号、计划、设备上限与到期时间。签名私钥只留服务端；客户端固定公钥。

## 客户端与编辑器边界

`MbsVerifyEditorGrant` 仅验证响应；`MbsEditorGrantAllowsEditing` 判断是否有有效激活；`MbsHasVerifiedEditorLicense` 是已加载、已核验且未到期的最终本机决定。原生桥只能查询此决定，找不到自有模块或没有有效授权时返回拒绝。

迁移后的原生入口不能调用原授权函数作为回退。未知功能／状态必须登记为未迁移，不能默认为允许，也不能让旧会员状态使其通过。仍依赖原厂服务器的服务必须完成自有服务实现后才算迁移，不将本站授权伪装成原厂服务凭证。

## 生命周期

- 启动：从本机私有目录读取签名缓存，完整验签和绑定校验后才能恢复编辑授权；同时联网同步。
- 运行：沿用现有五分钟续期。离线仅使用尚未过期的有效签名租约，不延长、不重新生成有效期。
- 到期／签名撤销响应：清除编辑授权并广播自有授权状态变化；阅读、保存已有工作和重新激活的具体边界必须完成各编辑器验收后确定，不以旧试用态续命。
- 退出／切换账号：清除原账号授权，取消旧请求，以代际计数防止迟到响应恢复旧账号权限。
- 管理员撤销：客户端联网续期时同步；离线缓存直到签名租约到期，不能宣称即时远程撤销。

账号一年授权期限与本机签名租约到期分开。租约不超过会话、授权码到期及现有三十天上限；不把短期租约日期当作授权码终止日期。

## 完成标准与回退

必须验证 Word／表格／演示／PDF 的创建、编辑、保存、重开，PDF 文字、图章、水印，以及首次安装、切换账号、无授权、到期、撤销、设备超限、断网、缺少自有模块等场景。还必须证明旧激活码、旧 SN、旧授权文件和旧会员态不会影响结果。

未通过前不得作为“完全脱离版”安装或发版。只读分析、单元测试或四个入口替换都不能单独满足此标准。

回退程序到已校验 0.1.40；网站代码与业务数据库分开回退。默认保留当前账号、会话和授权业务数据，不把旧快照中的有效状态覆盖已撤销记录。
