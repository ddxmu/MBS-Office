# 授权体系迁移分析与当前进度

## 当前结论

自有网站的登录、授权码、设备绑定和签名租约协议已经存在，可作为唯一授权服务。已核实的原生入口可以接入此决定。

目前不能认定整个编辑器已完全脱离。现有材料是反编译证据及自研集成层，仍有未替换的内部授权状态机、原生回调和其他功能权限查询。本机已安装 0.1.41 网站授权候选；0.1.40 保留为安全回退基线，尚未公开发布 0.1.41。

## 第一阶段隔离改动

1. 区分“签名响应有效”与“存在有效编辑激活”，已签名但到期／撤销／设备超限／无激活的状态不能开启编辑。
2. 已核实的四类 PDF 编辑／图章查询不再在 Mbs 授权无效时回退到旧会员判断。其他／混合权限查询仍需继续迁移，不能当作完全独立。
3. 七个已审计原生管理器方法改为 dlsym 查询 MbsHasVerifiedEditorLicense，找不到自有模块即拒绝；不再把原配置键的默认值当作授权，也不执行旧判断回退。
4. 新逻辑先进入隔离候选，按用户后续要求停止文档功能验收后，本机 /Applications 已安装完整候选。没有上线官网改动。原生库变更不能使用现有仅含自研模块的增量包交付。

测试已覆盖签名／账号／设备／会话／nonce／到期／篡改、无激活状态、PDF 禁止旧权限回退、ARM64 桥缺少自有模块时拒绝、有效与无效决定、回退失败恢复和业务数据保留。另已验证当前官网会话的真实续期及固定公钥验签，通过账号状态、定时到期、撤销、设备超限、写入失败与退出测试。

## 最新确认的实施范围

按用户最新要求保留现有编辑内核，实施网站认证适配，不重写／替换编辑器。原计划继续文档回归，后按用户要求停止，转为授权验收。未覆盖路径继续明确记录，不把接入自有网站等同于整个编辑器已重写或所有旧模块已移除。

- 原编辑内核保持不变。停止新增文档功能验收，仅继续授权接入和授权状态验证。
